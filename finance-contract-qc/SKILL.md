# 财务合同质检（合同/补充协议 · 供应商信息一致性）

一条主线：**定位合同类附件 → 抽取供应商名称与账号 → 与报账单填写值逐条比对 → PASS / HOLD**。

本流程只判断两件事：

1. 报账单「员工/供应商-户名」是否等于合同/补充协议中的「供应商名称」。
2. 报账单「员工/供应商-银行账号」是否等于合同/补充协议中的「供应商账号」。

除此之外不判断金额、付款方式、发票、业务类别等内容。规则没写的，一律不判。

> 规则事实源：`质检workflow/财务_合同质检.json`。各 reference 末尾标注了对应节点 ID；JSON 变更后按节点 ID 同步 reference，避免文档与实现漂移。

## 一、输入（4 项，按字段名解析）

| 输入 | 形态 | 用途 |
|------|------|------|
| 用户问题 | 字符串 | 触发质检；不参与字段比对 |
| 报账单信息 | JSON 字符串 | 取户名、银行账号、合同名称、业务类别 |
| 附件列表 + 电子影像 | JSON 数组字符串 | 合并为统一文件列表，再分类 |
| 稽核要素 | JSON | 取「稽核行号」，原样写回判断结果 |

报账单样例、字段别名与空值兜底见 `references/01-receive-inputs.md`。

## 三、判定总原则

- **白名单优先。** 命中白名单或名称长度 < 4，直接 PASS，不进入附件处理。
- **补充协议优先，合同补缺。** 有补充协议先读补充协议；某字段为空时再用合同同名信息补齐。
- **多份协议允许任意一条匹配。** 名称与账号在同一条记录中同时相等，即视为匹配。
- **空值口径分两种。** 单份协议、严格比对分支按字面相等；附件兜底分支（提示词明确写「为空则默认对应字段无误」）空字段不判错。按 `references/08-core-check.md` 的分支表执行。
- **只输出 JSON。** 不写报告、不写表格、不写「以下是质检结果」。
- **不臆造合同值。** 提取不到就留空；空值参与比对，不得用报账单值反填合同值。

## 四、输出契约

```json
{
  "判断结果": [
    { "稽核行号": 1, "判断结果": "HOLD" }
  ],
  "问题列表": [
    {
      "一类问题": "报销单填写问题",
      "二类问题": "供应商信息错误",
      "问题描述": "报账单户名为「A」，合同补充协议供应商名称为「B」，不一致（来源附件：合同补充协议，url：...）"
    }
  ]
}
```

- `判断结果`：固定一条，`稽核行号` 取自稽核要素，`判断结果` 只能是 `PASS` / `HOLD`。
- `问题列表`：PASS 时必须是 `[]`；HOLD 时每类问题一条，名称与账号同时不一致合并为一条。
- `问题描述`：必须包含报账单值、合同值、违反了哪条规则、来源附件链接。

完整字段与示例见 `references/09-output-verdict.md`。

## 五、硬约束

1. **只输出 JSON。** 前后不加任何说明文字。
2. **只判两条规则。** 不引入通用知识、业务惯例或常识推断。
3. **一条不漏、一条不多。** 判断结果固定一条，稽核行号原样保留。
4. **白名单短路。** 命中即 PASS，不再读任何附件。
5. **原件只读。** 不修改、不重命名、不覆盖用户的报账单与附件；本地副本只用于识别。
6. **提取留痕（不输出）。** 结论要能指出来源文件与位置；`问题描述` 引文克制，一般 ≤60 字。
7. **空值按分支处理。** 读不到时按对应分支的空值口径处理：严格分支按字面比较，只有附件兜底分支允许空字段不判错；问题描述里要说明来源。
8. **问题分类固定。** 一级只用「报销单填写问题」，二级只用「供应商信息错误」，不得自创。
