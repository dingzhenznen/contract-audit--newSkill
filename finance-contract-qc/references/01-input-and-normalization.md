# 01 · 输入接收与报账单字段归一化

> 覆盖 workflow 步骤 1 + 4：收齐输入，并把报账单字段取出来、洗干净。

## 本文包含

- 一、入口接收：四类输入、稽核要素解析、空值兜底
- 二、报账单字段提取：户名/账号别名链、补充信息兜底、清洗规则、输出

## 一、入口接收

### 目标

把一次合同质检需要的四类输入收齐，并统一成后续步骤可直接读取的上下文字段。本步骤只做**接收、解析、校验**，不判断任何风险。

### 输入清单

| 变量 | 业务名称 | 类型 | 必填 | 说明 |
|------|----------|------|------|------|
| `userChatInput` | 用户问题 | string | 是 | 触发语句，例如「这份报账单的供应商信息对不对」；不参与字段比对 |
| `x4nG7TQ6` | 报账单信息 | string（JSON） | 是 | 报账单全量 JSON，字段名见第二节 |
| `mvo4GuBm` | 附件列表 | string（JSON 数组） | 是 | 每项至少含 `filename`、`url` / `url-origin` |
| `pMjLGMvk` | 电子影像 | string（JSON 数组） | 是 | 与附件列表同构，来自电子影像系统 |
| `hSpFRyIb` | 稽核要素 | string（JSON） | 是 | 取其中的「稽核行号」写回结果 |

### 稽核要素解析

稽核要素可能是对象，也可能是数组。统一按下面规则取行号：

```js
const raw = JSON.parse(稽核要素);
const checkNum = Array.isArray(raw) ? raw[0]?.["稽核行号"] : raw["稽核行号"];
```

行号缺失时保留空字符串，不要自行编造；输出时原样带回。

### 空值与异常

- 报账单 JSON 解析失败：业务字段全部按空字符串处理，后续走空值口径。
- 附件列表 / 电子影像为空字符串或 `null`：按空数组处理。
- 户名或账号兜底仍取不到：保留空字符串，**不得用另一侧的值反填**。
- 业务类别缺失：文件分类按普通（非「对公预付款」）提示词处理。

### 本步骤产出

```json
{
  "userQuestion": "这份报账单的供应商信息对不对",
  "report": {
    "account_name": "河南和之也商贸有限公司",
    "account": "6222020200112233445",
    "contract_name": "2024年度经销合同",
    "check_num": "1",
    "business_type": "营销费用"
  },
  "attachments": [],
  "images": [],
  "checkElements": { "稽核行号": 1 }
}
```

### 对应节点

- `448745` workflowStart
- `x4nG7TQ6` / `mvo4GuBm` / `pMjLGMvk` / `hSpFRyIb` 对话变量

### 易错点

- 不要只读 `报账信息-员工/供应商-户名`；老单据常用别名或补充信息。
- 不要把「附件列表」和「电子影像」当成同一份数据去重两次；两者都要并入统一下游。
- 稽核行号是**字符串还是数字**不影响判定，但输出类型要与输入保持一致。

## 二、报账单字段提取与清洗

### 目标

从报账单 JSON 中取出合同质检需要的 4 个报账单字段，并结合第一节的 `check_num`，共 5 个值；统一清洗后供后续与合同侧比对。

### 字段来源

| 输出字段 | 来源 | 必填 | 用途 |
|----------|------|------|------|
| `account_name` | 报账单户名字段（见别名链） | 是 | 与「供应商名称」比对 |
| `account` | 报账单银行账号字段（见别名链） | 是 | 与「供应商账号」比对 |
| `contract_name` | `报账信息-合同名称` | 否 | 仅留痕，当前不参与判定 |
| `business_type` | `报账信息-业务类别` | 否 | 文件分类时判断「对公预付款」 |

> 注意：`check_num` **不在报账单里**，不要从报账单找「稽核行号」。

### 户名别名链

按从左到右第一个非空值取：

```text
报账信息-员工/供应商-户名
→ 报账信息-供应商名称-户名
→ 报账信息-员工/供应商名称-户名
→ 报账信息-开户名
→ 报账信息-员工/供应商 信息补充（兜底）
```

### 银行账号别名链

```text
报账信息-员工/供应商-银行账号
→ 报账信息-供应商名称-银行账号
→ 报账信息-员工/供应商名称-银行账号
→ 报账信息-银行账号
→ 报账信息-员工/供应商 信息补充（兜底）
```

### 补充信息兜底

只有当主字段为空时才启用。补充信息通常是空格分隔的键值串：

```text
员工/供应商 开户名:河南和之也商贸有限公司 账号:6222020200112233445
```

解析规则：

```js
const parts = supplementInfo.split(" ");
accountName = parts[1]?.split(":")[1];  // 第 2 段冒号后的值
account     = parts[2]?.split(":")[1];  // 第 3 段冒号后的值
```

示例：

```text
parts[0] = "员工/供应商"
parts[1] = "开户名:河南和之也商贸有限公司"  → 户名
parts[2] = "账号:6222020200112233445"      → 账号
```

格式不符合（段数不足、没有冒号）时保留空字符串，**不要用另一侧的值反填**。

### 清洗规则

清洗在提取阶段完成一次，后续比对直接使用清洗后的值。

#### 户名

先去掉业务附注，避免「（盖章）」「（代收）」被当成名称的一部分：

- 括号内为 `盖章`、`代收`、`签章`、`财务专用章`、`合同专用章` 的整段删除；
- 只删这些已知附注，不删其他括号内容（如「中国银行（香港）」）。

去掉：

- 空白字符（空格、换行、制表符）
- 半角/全角括号：`()（）[]【】{}`
- 书名号：`<>《》`
- 引号：`" ' “ ” ‘ ’`
- 连字符、下划线：`- _`
- 常见符号：`+ = % # @ ! ~ \` $ ^ & * | \ / : ; ? , .`

只保留中文、英文字母、数字。

等价正则：

```js
name.replace(/[\s()\[\]{}<>《》""''\-_+=%#@!~`\$\^&\*\|\\\/:;?,.【】（）]+/g, "")
```

示例：

```text
"河南和之也商贸有限公司（盖章）" → "河南和之也商贸有限公司"
"河南 和之也 商贸有限公司"       → "河南和之也商贸有限公司"
```

#### 银行账号

先去各种减号：

```text
- – — ― −
```

再去空白、括号、引号、下划线及常见符号，保留数字和字母，最后 `trim()`。

等价正则：

```js
account
  .replace(/[\-\u2013\u2014\u2015\u2212]/g, "")
  .replace(/[\s$${}<>《》""''_+=%#@!~`\$\^&\*\|\\:;?,.【】（）]+/g, "")
  .trim()
```

示例：

```text
"6222 0202 0011 2233 445" → "6222020200112233445"
"6222-0202-0011-2233-445" → "6222020200112233445"
```

### 输出

```json
{
  "account_name": "河南和之也商贸有限公司",
  "account": "6222020200112233445",
  "contract_name": "2024年度经销合同",
  "check_num": "1",
  "business_type": "营销费用"
}
```

### 对应节点

- `hBOMed8IM8YJlrQt` 报账单合同字段提取
- `hSpFRyIb` 稽核要素（提供 `check_num`）

### 易错点

- 只读一个字段名会漏掉大量老单据，必须按别名链依次回退。
- 补充信息按**单个空格**切分；多个连续空格可能导致段位偏移，此时宁可留空也不要猜。
- 户名清洗不要把中文、字母、数字以外的内容保留下来，否则「（盖章）」「（代收）」会造成假不一致。
- 账号清洗不要保留空格和连字符，否则 `6222 0202...` 与 `62220202...` 会被判为不一致。
- `contract_name` 提取后当前没有参与判定，不要拿它去做合同匹配。
