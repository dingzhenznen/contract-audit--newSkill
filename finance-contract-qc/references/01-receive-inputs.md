# 01 · 入口接收报账单、附件与稽核要素

## 目标

把一次合同质检需要的四类输入收齐，并统一成后续步骤可直接读取的上下文字段。本步骤只做**接收、解析、校验**，不判断任何风险。

## 输入清单

| 变量 | 业务名称 | 类型 | 必填 | 说明 |
|------|----------|------|------|------|
| `userChatInput` | 用户问题 | string | 是 | 触发语句，例如「这份报账单的供应商信息对不对」；不参与字段比对 |
| `x4nG7TQ6` | 报账单信息 | string（JSON） | 是 | 报账单全量 JSON，字段名见下表 |
| `mvo4GuBm` | 附件列表 | string（JSON 数组） | 是 | 每项至少含 `filename`、`url` / `url-origin` |
| `pMjLGMvk` | 电子影像 | string（JSON 数组） | 是 | 与附件列表同构，来自电子影像系统 |
| `hSpFRyIb` | 稽核要素 | string（JSON） | 是 | 取其中的「稽核行号」写回结果 |

## 报账单字段别名

报账单在不同业务系统导出的字段名略有差异，按**从左到右第一个非空值**取。

### 户名

```
报账信息-员工/供应商-户名
→ 报账信息-供应商名称-户名
→ 报账信息-员工/供应商名称-户名
→ 报账信息-开户名
→ 兜底：报账信息-员工/供应商 信息补充
```

兜底解析：把补充信息按空格切分，取第 2 段（下标 1），再按英文冒号 `:` 切分，取冒号后的值。

示例：

```
报账信息-员工/供应商 信息补充 = "员工/供应商 开户名:河南和之也商贸有限公司 账号:6222020200112233445"
→ 户名 = 河南和之也商贸有限公司
```

### 银行账号

```
报账信息-员工/供应商-银行账号
→ 报账信息-供应商名称-银行账号
→ 报账信息-员工/供应商名称-银行账号
→ 报账信息-银行账号
→ 兜底：报账信息-员工/供应商 信息补充
```

兜底解析：同样按空格切分，取第 3 段（下标 2），再按英文冒号 `:` 切分，取冒号后的值。

### 其他字段

| 字段 | 来源 | 用途 |
|------|------|------|
| `contract_name` | `报账信息-合同名称` | 仅提取留痕，当前不参与判定 |
| `business_type` | `报账信息-业务类别` | 文件分类时判断是否「对公预付款」 |
| `check_num` | 稽核要素中的「稽核行号」 | 原样写入输出 |

## 稽核要素解析

稽核要素可能是对象，也可能是数组。统一按下面规则取行号：

```js
const raw = JSON.parse(稽核要素);
const checkNum = Array.isArray(raw) ? raw[0]?.["稽核行号"] : raw["稽核行号"];
```

行号缺失时保留空字符串，不要自行编造；输出时原样带回。

## 空值与异常

- 报账单 JSON 解析失败：四个业务字段全部按空字符串处理，后续走空值口径。
- 附件列表 / 电子影像为空字符串或 `null`：按空数组处理。
- 户名或账号兜底仍取不到：保留空字符串，**不得用另一侧的值反填**。
- 业务类别缺失：文件分类按普通（非「对公预付款」）提示词处理。

## 易错点

- 不要只读 `报账信息-员工/供应商-户名`；老单据常用别名或补充信息。
- 不要把「附件列表」和「电子影像」当成同一份数据去重两次；两者都要并入统一下游。
- 稽核行号是**字符串还是数字**不影响判定，但输出类型要与输入保持一致。
