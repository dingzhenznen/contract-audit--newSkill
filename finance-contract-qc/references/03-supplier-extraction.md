# 03 · 供应商名称与账号提取

> 覆盖 workflow 步骤 5：从合同/补充协议中提取供应商名称与账号，并完成配对和清洗。

## 本文包含

- 目标与输入输出
- 文件类型路由
- 供应商名称提取优先级（P0/P1/P2）
- 供应商账号提取与排除项
- 名称过滤、配对、多账号拆分、提取后清洗
- 对应节点与易错点

## 目标

从合同 / 合同补充协议中提取「供应商名称 + 供应商账号」对。一个文件可以产出多条记录；没有账号时账号留空字符串。

## 输入与输出

```json
// 输入：文件 URL 数组
["https://.../supplement-1.pdf", "https://.../supplement-2.jpg"]

// 输出：每个文件一条结果，columns 内是提取到的记录
[
  {
    "url": "https://.../supplement-1.pdf",
    "columns": [
      { "供应商名称": "杭州云智数据服务有限公司", "供应商账号": "110012345678" }
    ]
  }
]
```

后续清理节点会把每个文件的 `columns` 展开成扁平的「一条记录 + 来源 URL」列表。

## 文件类型路由

逐个文件处理：

| 类型 | 处理 |
|------|------|
| `.pdf` | 先转图片，再用视觉模型提取 |
| `.png` / `.jpg` / `.jpeg` | 直接用视觉模型提取 |
| 其他文档 | 先解析文本，再用文本模型提取 |

多页 PDF / 多张图片按**同一份文档**处理，不要逐页各提一份然后互相覆盖。

## 供应商名称提取优先级

按 P0 → P1 → P2，命中即停止：

### P0 · 专用 / 监管账户

标签包含以下任意关键词时，提取标签后的完整专户名称：

- 专用账户
- 监管账户
- 保证金账户
- 工资专户

示例：

```text
农民工工资专用账户：深圳市XXX司年产30万千升啤酒新建项目农民工工资专用账户
→ 供应商名称 = 深圳市XXX司年产30万千升啤酒新建项目农民工工资专用账户
```

专户名称必须**整段保留**，不要截断成公司名。

### P1 · 明确户名标签

标签为以下任意一种时，取标签后的值：

- 户名
- 收款方
- 销售方
- 开户名
- 全称

### P2 · 公司法定名称

以上标签都不存在时，取与账号语义最近、带公司后缀的全称：

- 有限公司
- 集团
- 厂
- 局

### 排除项

- 自然人姓名
- 不含「账户 / 专户」字样的纯项目名称
- 品牌简称

## 供应商账号提取

### 合法格式

- 连续纯数字字符串；
- 允许中间有空格或连字符，输出时去掉。

### 必须出现在账户语境

账号附近要出现以下关键词之一：

- 账号
- 专户账号
- 收款账号
- 银行卡号

### 严格排除

- 印章 / 签章区数字
- 统一社会信用代码 / 税号（含字母，或 91 / 92 开头）
- 发票代码
- 订单号
- 电话
- 身份证号
- 内部流水号
- 防伪码
- 页眉页脚水印数字

## 名称过滤规则（最高优先级）

在配对前执行。命中即丢弃该条记录，不输出：

- 账户户名包含 `雪花`、`金沙`、`酒业`（不区分大小写）；
- 结合图文判断属于水印、测试数据或非真实交易主体。

这三个词是**付款方/酒业内部主体**的识别词，不是白名单。不要把「贵州金沙窖酒酒业有限公司」当成供应商。

## 配对规则

1. **就近绑定**：每个有效户名与语义最近、且合法的账号配对；优先同一行、同一语义块。
2. **禁止跨段匹配**：户名和账号在相邻行或同一表格行时，不得跳到远处找另一个公司的账号。
3. **多账号拆分**：账号用 `/`、`、` 或换行分隔时，拆成多条记录，户名相同、账号不同。
4. **无账号**：户名合法但附近没有有效账号时，账号返回 `""`，不要丢记录。

示例：

```text
收款方：杭州云智数据服务有限公司
账号：110012345678 / 110087654321
→ [
  { "供应商名称": "杭州云智数据服务有限公司", "供应商账号": "110012345678" },
  { "供应商名称": "杭州云智数据服务有限公司", "供应商账号": "110087654321" }
]
```

## 提取后的清洗

对每条记录的名称和账号再做一次清洗，规则同 `references/01-input-and-normalization.md`：

- 名称：去空白、括号、引号、连字符、标点，只保留中英文和数字；
- 账号：去各种减号、空白、括号、标点。

清洗后名称为空、账号为空的记录先保留，交给 `references/04-whitelist-and-branching.md` 的去空/合并步骤统一处理。

## 易错点

- 不要把税号、发票代码、电话当账号；账号必须在「账号/收款账号/银行卡号」语境里。
- 不要因为名称里含「金沙」就一律丢弃；过滤词针对的是**供应商户名**，不是报账单付款方。
- 专户名称要整段保留，截成公司名会与报账单户名对不上。
- 多页文档要合并理解，不能第一页提名称、第二页提账号后互相当成两份记录。
- 名称和账号必须就近配对；跨段配对会造成「名称对、账号对，但不是同一家」的假 PASS。
