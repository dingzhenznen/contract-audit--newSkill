# 06 · 输出判定：PASS / HOLD

> 覆盖 workflow 步骤 9：只输出一段可直接解析的 JSON。

## 本文包含

- 输出结构与字段规则
- 问题分类与问题描述模板
- PASS / HOLD 示例
- 输出纪律与输出前自检

## 目标

只输出一段 JSON，供下游系统直接解析。不要报告、表格、Markdown 代码围栏或前后说明。

## 输出结构

```json
{
  "判断结果": [
    {
      "稽核行号": 1,
      "判断结果": "HOLD"
    }
  ],
  "问题列表": [
    {
      "一类问题": "报销单填写问题",
      "二类问题": "供应商信息错误",
      "问题描述": "报账单中'员工/供应商-户名'为'河南和之也商贸有限公司'，合同补充协议供应商名称为'河南和之也商贸'，不一致（来源附件：合同补充协议，url：https://...）"
    }
  ]
}
```

## 字段规则

### `判断结果`

- 固定为数组，**只放一条**。
- `稽核行号`：取自稽核要素，类型与输入保持一致（数字或字符串），不要改写。
- `判断结果`：只能是 `PASS` 或 `HOLD`。
  - 两条规则都满足 → `PASS`；
  - 任意一条不满足 → `HOLD`。

### `问题列表`

- `PASS` 时必须是空数组 `[]`。
- `HOLD` 时放问题对象；名称和账号同时不一致时合并为**一条**。
- 实践中通常只有 0 或 1 条，不要按字段拆成两条。
- 键名固定为 `一类问题`、`二类问题`、`问题描述`。

### 问题分类

```json
{
  "一类问题": "报销单填写问题",
  "二类问题": "供应商信息错误"
}
```

不得自创一级/二级分类，不得把金额、付款方式等问题混进来。

## 问题描述模板

### 只有名称不一致

```text
报账单中'员工/供应商-户名'为'{报账单户名}'，合同补充协议供应商名称为'{合同供应商名称}'，不一致（来源附件：合同补充协议，url：{url}）
```

### 只有账号不一致

```text
报账单中'员工/供应商-银行账号'为'{报账单账号}'，合同补充协议供应商账号为'{合同供应商账号}'，不一致（来源附件：合同补充协议，url：{url}）
```

### 名称和账号都不一致

```text
报账单中'员工/供应商-户名'为'{报账单户名}'、'员工/供应商-银行账号'为'{报账单账号}'，与合同补充协议供应商名称'{合同供应商名称}'、账号'{合同供应商账号}'不一致（来源附件：合同补充协议，url：{url}）
```

### 来源附件写法

- 补充协议来源写：`（来源附件：合同补充协议，url：...）`
- 合同来源写：`（来源附件：合同，url：...）`
- 多份协议时，链接指向实际用于比对的记录；如果无法确定，列出最相关的一条，不要编造链接。
- 原文引文克制，一般 ≤60 字；名称和账号本身可以完整保留。

## PASS 示例

```json
{
  "判断结果": [
    {
      "稽核行号": 1,
      "判断结果": "PASS"
    }
  ],
  "问题列表": []
}
```

```json
  "判断结果": [

      "判断结果": "HOLD"
    }
  ],
  "问题列表": [
    {
      "一类问题": "报销单填写问题",
      "二类问题": "供应商信息错误",

    }
```

```json
    }
  ]

```

## 输出纪律

- 只输出 JSON 文本，2 空格缩进。
- 不要输出 `riskLevel`、`summary`、`checkRes` 等合同审计字段；本流程不是风险分级，是 PASS/HOLD。
- 不要在 JSON 前后加「以下是质检结果」「希望有帮助」等文字。
- 不要在 JSON 里加注释、Markdown 代码围栏或尾随逗号。
- 不要输出思考过程、更正说明或多余字段。

## 输出前自检

- [ ] `判断结果` 只有一条，`稽核行号` 与输入一致
- [ ] `判断结果` ∈ {`PASS`, `HOLD`}
- [ ] `PASS` 时 `问题列表 == []`
- [ ] `HOLD` 时问题列表非空，且名称/账号问题已合并
- [ ] 问题描述包含报账单值、合同值、「不一致」字样和来源链接
- [ ] 问题分类固定为「报销单填写问题 / 供应商信息错误」
- [ ] JSON 之外没有任何内容
