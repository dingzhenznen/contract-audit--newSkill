# 08 · 核心质检：户名与账号一致性

## 两条规则

只判断这两条，其他字段一律不判：

1. 报账单「员工/供应商-户名」== 合同/补充协议「供应商名称」。
2. 报账单「员工/供应商-银行账号」== 合同/补充协议「供应商账号」。

两条都相等 → `PASS`；任意一条不相等 → `HOLD`。

## 比对前状态

进入本步骤时，两侧值应已完成清洗：

- 报账单侧：`account_name`、`account`（见 `references/04-extract-report-fields.md`）；
- 合同侧：一条或多条 `{供应商名称, 供应商账号}` 记录（见 `references/05-extract-supplier-info.md` / `07-protocol-branching.md`）。

比对使用**清洗后的字符串精确相等**：

```js
nameMatch    = reportName    === supplierName;
accountMatch = reportAccount === supplierAccount;
```

不做模糊匹配、不做包含匹配、不做相似度、不做大小写转换。

## 单条记录

只有一条供应商记录时：

```text
名称相等 且 账号相等 → PASS
否则                 → HOLD
```

## 多条记录

有多条供应商记录时，按「同一条记录同时匹配」处理：

```text
存在任意一条记录 i，使得：
  reportName    === record[i].供应商名称
  reportAccount === record[i].供应商账号
→ PASS

所有记录都不满足 → HOLD
```

不要把名称匹配记录 A、账号匹配记录 B 拼成一个 PASS；名称和账号必须来自同一条记录。

## 空值口径

空值口径**按分支**执行，不能全局一刀切。

| 分支 | 使用场景 | 空值处理 |
|------|----------|----------|
| 严格比对 | 单份补充协议、多份补充协议合并后、合同提取后字段齐全 | 按字面相等：空 vs 非空 → 不一致；空 vs 空 → 一致 |
| 附件兜底 | 附件侧字段为空，且没有更可靠的合同信息 | 该字段视为「无误」，只比较非空字段 |

### 附件兜底分支

对应提示词节点：`uXHCwmNyAhHUT3Xd` 执行质检#10。

该提示词明确写了：

> 若「供应商名称」或「供应商账号」提供内容为空则默认对应字段无误，只有字段值不为空时才比较是否相等。

即：

```text
合同侧名称为空 → 名称字段不判错
合同侧账号为空 → 账号字段不判错
合同侧有值     → 必须与报账单值精确相等
```

这个分支只用于「没有更可靠合同信息、只能拿附件兜底」的场景，不能扩大到单份补充协议的严格比对。

## 问题合并

- 名称不一致、账号一致 → 1 条问题；
- 名称一致、账号不一致 → 1 条问题；
- 名称和账号都不一致 → **合并为 1 条问题**，描述里同时写两个字段；
- 同一问题在多份协议中重复出现 → 合并为 1 条，不按协议数量重复输出。

## 问题分类

固定使用：

```json
{
  "一类问题": "报销单填写问题",
  "二类问题": "供应商信息错误"
}
```

问题类型列表的原始表述是「一级问题 / 二级问题」，输出示例使用「一类问题 / 二类问题」；以输出示例的键名为准。

## 判定为 HOLD 的典型情形

| 情形 | 结果 |
|------|------|
| 报账单户名与合同供应商名称不同 | HOLD |
| 报账单账号与合同供应商账号不同 | HOLD |
| 名称相同、账号不同 | HOLD |
| 名称不同、账号相同 | HOLD |
| 名称与账号都不同 | HOLD，合并为一条问题 |
| 多记录中任意一条名称+账号都相同 | PASS |
| 名称匹配记录 A、账号匹配记录 B，但没有同一条同时匹配 | HOLD |

## 判定为 PASS 的典型情形

- 白名单命中（第 06 步已短路）；
- 单条记录名称和账号都相等；
- 多条记录中存在一条名称和账号都相等；
- 附件兜底分支中，合同侧对应字段为空，且非空字段都相等。

## 禁止事项

- 不要因为「看起来是同一家公司」就放过简称/全称差异；必须先经过第 04/05 步清洗，清洗后仍不等就是不等。
- 不要用「名称包含关系」代替相等，例如「河南和之也商贸」与「河南和之也商贸有限公司」不是相等。
- 不要引入金额、付款方式、发票、业务类别等规则。
- 不要因为合同侧为空就默认 PASS；只有附件兜底分支明确允许空字段不判错。
- 不要输出 `PASS` 以外的问题列表内容；PASS 时问题列表必须是 `[]`。
