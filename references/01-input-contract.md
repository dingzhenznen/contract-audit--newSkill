# 01 · 输入的固定解析

两种输入的格式固定，按位置解析即可，不需要做通用适配。**不要向用户追问字段含义**，按本文件照做。

---

## 1. 规则集：`items[]` 三个字段怎么用

### 1.1 `helpDesc` → "从哪里取"（合同侧）

固定句式与解析规则：

| 句式片段 | 解析结果 |
|---------|---------|
| `关键字'XXX'后提取` / `关键字“XXX”后提取` | 锚点 = `XXX`，**逐字符照抄**（含全角括号、冒号） |
| `关键字'XXX'下方的表格中` | 锚点 = `XXX` **且**进入表格模式（两种句式会合并出现，要一起识别） |
| `下方的表格中` | 表格模式（`TABLE`，取锚点后第一个表格） |
| `提取'A、B、C'` | 需要提取的列名列表，按顿号/逗号切分；括号内是单位说明，不参与表头匹配（`建议销售价(元/瓶)` → 匹配「建议销售价」） |
| `下划线上的文字` | 取下划线（填空线）上或紧邻其上方的手写/填写内容 |
| `只提取1次` | 取首次命中即停，**其余命中不取、不并入** |
| `未识别到信息时显示空字符串` | 兜底值 = `""`（**唯一的兜底口径**） |
| （无 `helpDesc`） | 该条为"不判断"类规则，不做提取 |

> 解析可用一条正则兜底取锚点：`关键字\s*['“](.+?)['”]`（引号可能是半角 `'…'` 或全角 `“…”`，都要匹配）。
> 实测 11 条规则里出现的句式：`关键字'甲方（供货方）：'后提取`、`关键字'乙方（购货方）：'后提取`、
> `关键字'有效期间自'后提取`、`关键字'销售合作方式：'后提取下划线上的文字`、
> `关键字'2.1乙方经销啤酒的品种、规格、价格以及数量等。'下方的表格中，提取'产品品种、约定销量（件）'`（表格类，3 条）、
> `关键字'4.1 …销售产品折扣政策为'后提取下划线上的文字`。

**锚点纪律**：
1. 先用原样匹配（含全半角差异）；原样不中再退化为"忽略全半角差异"匹配，命中后仍继续执行。
2. 锚点未命中 → **不替换近义词、不做近似猜测**，按兜底值 `""` 参与比对，等级取该条 `judgeRule` 的等级。
3. 同一锚点命中多次且值不一致 → 取首次，其余忽略。

### 1.2 `judgeRule` → "判什么等级"（唯一的等级来源）

| 句式 | 判定 |
|------|------|
| `…不一致，则判断为“中风险”` | 不一致 → `中风险`；一致 → `通过` |
| `…不一致，则判断为“高风险”` | 不一致 → `高风险`；一致 → `通过` |
| `…不一致，则判断为“低风险”` | 不一致 → `低风险`；一致 → `通过` |
| `不判断，只展示TPM值` | 恒为 `通过`，`auditDesc` 留空 |
| 以上都不匹配（规则集没写等级） | 按"不判断"处理 → `通过`，`auditDesc` 留空 |

解析要点：
- 等级字样在**引号内**（全角 `“”` 或半角 `""`），取引号内的 `高风险 / 中风险 / 低风险`。
- **不要**因为"价格问题看着更严重"就把中风险提到高风险，反之亦然。
- 值不同、行缺失、合同侧为空 —— 本项目规则集不区分这些情形，**一律落同一档**。

### 1.3 `outputDesc` → "值怎么写"

只在需要固定书写格式时使用，目前只有一个：协议有效期。

```jsonc
"outputDesc": "{ \"协议有效期\":\"XXXX年XX月X日-XXXX年XX月X日\" }"
```

→ 输出与 `auditDesc` 里的日期一律写成 `YYYY年MM月DD日-YYYY年MM月DD日`（如 `2024年07月23日-2025年06月30日`），个位月/日补零。

## 2. 表单与合同列表：字段字典

```
扁平字段（直接取值）
  customerName          经销商名称
  terminalName          终端名称
  cooperationModeDesc   合作方式
  estimateTerminalCost  预计总投入
  protocolStartTime     协议有效期·起点
  protocolEndTime       协议有效期·终点

重复项数组（保留行结构，不要压平成字符串）
  products[]            productName / salesCount / entryPrice / retailPrice / singleStandard
  contractFiles[]       contractCode / fileName / downloadUrl
```

## 3. 字段映射表（规则 `fieldName` → 表单取值）

**按 `fieldName` 匹配，不按 `fieldCode`**（`fieldCode` 随省份/规则集变化，`fieldName` 才是稳定的业务名）。

| 规则 `fieldName` | 表单取值 | 比对方式 |
|------------------|---------|---------|
| 经销商名称 | `customerName` | 单值 |
| 终端名称 | `terminalName` | 单值 |
| 协议有效期 | `protocolStartTime` + `protocolEndTime` | 单值（区间，各取日期部分） |
| 合作方式 | `cooperationModeDesc` | 单值 |
| 进店价 | `products[].entryPrice`（按产品行） | 行级集合 |
| 零售价 | `products[].retailPrice`（按产品行，**元/件**） | 行级集合（需单位折算，见 03 §4） |
| 预计销量 | `Σ products[].salesCount`（合计，单位：件） | 单值（与合同表格的销量列合计比） |
| 预计总投入 | `estimateTerminalCost` | 不判断（`judgeRule` 声明），`通过` |
| 随量折扣 / 固定折扣 / 其他折扣 | 表单无对应字段 | 视 `judgeRule`：不判断 → `通过`；要求判定 → 合同侧按兜底 `""`，两侧皆空 → 一致 → `通过` |
| 其它未列出的 `fieldName` | 表单无对应字段 | 同上 |

映射说明：
- **`customerName` 是经销商（合同甲方/供货方），`terminalName` 是终端（合同乙方/购货方）**，不要对调。
- 表单里没有"经销商名称/终端名称"这类中文字段，只有上表的英文键 —— 这是固定映射，不要因为字段名不同就判定"表单缺字段"。

## 4. 归一化口径（固定，不需要规则集授权）

| 层 | 处理 | 说明 |
|----|------|------|
| L1 空白 | 去首尾空白、连续空格合一、去零宽字符 | 始终启用 |
| L2 全半角 | 全角字母/数字/标点 → 半角；中文标点保留 | 始终启用 |
| L3 大小写 | 英文统一小写 | 始终启用 |
| L4 单位 | `ml/mL/毫升`→`ml`；`L/升`→`l`；零售价按件内瓶数折算（见 03 §4） | 按字段 |
| L5 数值 | 去千分位、去币种符号、去尾部 `.00`、按数值比较 | 按字段 |
| L6 日期 | `2026/1/1`、`2026年1月1日` → `2026年01月01日`；区间 `起点-终点` | 按字段 |
| L7 括号注释 | 剥离尾部括注 | **关闭**（`齐齐哈尔烤肉` 与 `齐齐哈尔家庭烤肉（心怡路）` 是不同写法，不抹平） |

**数值容差默认 0**（严格相等）。`3.80` 与 `3.8` 经 L5 归一化后相等；`66` 与 `60` 不等。

**红线**：归一化只消除排版噪音，不抹平实质差异。`北京某某商贸` ≠ `北京某某商贸有限公司`。
