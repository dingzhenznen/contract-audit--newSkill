# 02 · 合同侧取值（提取）

取值失败很常见（签名过期、图片旋转、手写潦草）。**先排除"取件"问题，再动结论** ——
但这条只适用于**下载链接**（§2.1，多试一次 URL 不增加读图次数）；
**读图不适用**：每页只读一次，读不清即按兜底取 `""`，不放大、不复读。

---

## 1. 提取五步法

对每条规则固定走这五步，**顺序不可颠倒**：

```
① 定锚点  anchors        → 在合同中定位，记录命中次数与位置
② 划范围  scope          → 从锚点出发确定"从哪里取到哪里"
③ 取形态  SINGLE / ROWS  → 取 1 个值 / 一串值 / 一张表的若干行
④ 归一化  normalize      → 去排版噪音（不改实质内容），见 01 §4
⑤ 留痕    trace          → 记下 文件 / 位置 / 首次读到的原文 / 置信度（不输出，见 §6）
```

任一步失败 → 该条合同值按 `helpDesc` 兜底取 `""`，**继续执行其余规则**，不要"往下试试看能不能捞到别的"。

---

## 2. 合同文件的读取

### 2.1 下载 URL 签名会过期 —— 优先试直连

`contractFiles[].downloadUrl` 带的是 COS 临时签名（`q-sign-time` 字段），**有效期通常只有 12 小时**，过期后直连返回 **403**。这是最高频的"合同无法解析"假象。

降级顺序（逐级尝试，命中即用）：

```
① 原样直连 downloadUrl（带签名）
② 失败 → 去掉 URL 上全部 query 参数，用同路径直连
     https://<bucket>.cos.<region>.myqcloud.com/<key>
   该前缀通常为公共读，可正常取到文件
③ 仍失败 → 才判定为"文件不可取"，该合同所有规则按兜底值处理
```

注意：默认 UA 可能被拒，请求要带 `User-Agent: Mozilla/5.0`。取到后核对字节数（正常合约照片 1~3 MB），确认不是错误页。

```python
# 可复用的取件逻辑
import urllib.request, os
url = "http://aiac-dsu-1259627966.cos.ap-guangzhou.myqcloud.com/aiac/2026-09-30/2105xxx.jpg?sign=..."
bare = url.split("?")[0].replace("http://", "https://")   # 降级：去签名走直连
for u in (url, bare):
    try:
        req = urllib.request.Request(u, headers={"User-Agent": "Mozilla/5.0"})
        data = urllib.request.urlopen(req, timeout=120).read()
        if len(data) > 100000:
            open(dest, "wb").write(data)
            break
    except Exception:
        continue
```

### 2.2 图片读取：整页直读，一页只读一次

**唯一路径 —— 没有第二遍。**

用运行环境自带的图像读取能力，把**整页原图完整读一次**，按锚点扫，不要逐字通读：

```
① 扫锚点（`甲方（供货方）：`、`有效期间自`、`2.1 乙方经销啤酒的品种、规格、价格以及数量等。`），
   确认命中位置；未命中按 §3.4 处理
② 锚点后取目标值；表格类先确认表头行，再逐行取值（§5）
③ 读到什么就记什么，当场留痕（§6），随即定稿
```

**一次读图就是最终答案**：读出来的值直接进比对，不再回头校对、不再补读。

实测（1080×1920 手机拍摄件）：整页直读可稳定拿到甲乙方名称、勾选态、表格整行数值、日期起止，
准确率不低于 OCR；**勾选态与手写体反而更准**（OCR 会把 `☑` 和 `□` 都读成"口"）。

**明确禁止的"提准"手段**（一律不做，纯浪费轮次）：

| 禁止动作 | 为什么不划算 |
|---------|-------------|
| 逐字放大复核（把某字裁到 20 倍再看一遍） | 手写体在原分辨率下已到该图的信息上限，放大只是放大 JPEG 噪点，判读结果不会更准 |
| 叠坐标网格 → 目视定位 → 精确切片 | 手机拍摄件有透视变形，凭缩略图估的坐标会偏 40~90 px，切偏了还得再来一次 |
| 同一页换种说法重读、重复读 | 同一张图、同一视角，得到的就是同一个答案 |
| 为"确认"再读一次同类字段 | 结论不会变，只多耗一轮 |

**读不清就取空。** 手写体、印章压字、失焦、反光导致某处读不出 —— 这是**常态而非异常**。
直接按 `helpDesc` 兜底取 `""` 参与比对，等级仍取该条 `judgeRule`。
**不要输出"疑似值"，也不要为了消除这点不确定去放大或复读。**

> 手写体本身就存在识别错误或识别不出的情况，放大没有实际作用；本流程的取舍是**速度优先**。
> 4 张图就是 4 次读图，**不存在第 5 次**。

### 2.3 方向校正

拍摄件常见整体旋转 90°/180°。判断方法：键盘、页眉等参照物文字方向。

- **整页直读时**：读图能力通常能自行适应旋转。**读出内容正常就直接用**，不做任何校正。
- **仅当整页明显错乱**（通篇无意义字符）时才校正：用 `Image.rotate(180, expand=True)`
  （顺时针 90° 的图用 `-90`）旋转后**补读一次**，**不要在旋转图上硬读**。
- 这次补读是"一页一次"里**唯一允许的例外**，且只允许一次；旋转后仍读不清 → 按兜底 `""`。

### 2.4 手写体：读一次，读到什么算什么

- 手写字（甲乙方名称、日期、折扣内容）是整页最不可靠的部分，**不单独确认、不放大复核**。
- 单字不确定（如"烤/烧"）但**不影响"与表单不一致"的结论**时，按首次读数直接落库，按规则等级输出。
- 整体不可辨 → 按兜底 `""` 处理，**不要输出疑似值**。

> 实测：OCR 把乙方手写"齐齐哈尔烤肉"读成"齐济哈尔烷肉"、印刷体"商贸"读成"商贤"；
> 整页直读这两处都对。**手写体上整页直读已接近该图的可用上限**，再放大也不会有新信息。

### 2.5 环境要求与移植（把本 skill 交给别人时必读）

本流程对运行环境只有**一个**硬要求：**能读图**。

| 环境 | 可用性 | 做法 |
|------|--------|------|
| 多模态 agent（任何带视觉模型的产品） | ✅ 直接可用 | 走 §2.2 唯一路径。**零依赖**，不需要任何脚本或 Python 包 |
| 仅有文本模型、无读图能力 | ⚠️ 需先补一件 | 必须外挂本地 OCR（如 `rapidocr_onnxruntime`，纯 CPU 可跑）把图转成带坐标的文本，再按 §3~§5 的锚点/表格程序取值；否则合同无法解析 |
| 图片取不到（离线 / 直连亦 403） | ❌ | 按 §2.1 降级；仍取不到 → 相关规则全部按兜底 `""` 处理，等级仍取 `judgeRule` |

**移植清单**：复制 skill 目录（`SKILL.md` + `references/` + `templates/`）到对方的 skills 目录即可。
目录内不含任何脚本、不含任何 Python 依赖，纯文本。

**读图能力自检**（30 秒，**只做一次**）：取一张合同页，整页读，找"表格第 4 行第 5 列"这类具体值。
答得出 → 环境可用，走 §2.2 唯一路径；答不出 → 走 OCR 兜底。
这是**环境选型**判断，不是逐字段校验，不要把它变成每份合同的例行复读。

## 3. 锚点定位细则

1. **逐字符照抄**：规则写 `甲方（供货方）：`（全角括号+全角冒号）就不能只找 `甲方(...)`。先原样匹配，再退化为"忽略全半角差异"匹配。
2. **`occurrence` 必须被尊重**：写"只提取 1 次"→ 取首次命中即停，剩余命中不取、不并入。
3. **锚点命中但后方无值**（如 `甲方：` 后直接换行）→ 兜底 `""`。
4. **锚点未命中** → 兜底 `""`。同时在线下记下"文档里包含锚点前 2~3 字的相似片段"，便于判断是锚点抄错还是合同版本不同。
5. **锚点歧义**（同一锚点含义不同）→ 取最靠近规则所述上下文的那处；无法判断 → 兜底 `""`。

**不要去近似替换锚点的近义词**。实测一例：规则锚点写「…销售产品**折扣**政策为」，合同原文是「…销售产品**合作**政策为」，一个字的差异导致锚点未命中、该条取空 —— 这是规则集需要修的地方，不是执行时该自己圆过去的地方。

## 4. 取值范围

| scope | 取值边界 | 注意 |
|-------|---------|------|
| `anchorToLineEnd` | 锚点后至该行结束 | `甲方：北京某某商贸有限公司` → 取 `北京某某商贸有限公司`（剥掉锚点本身） |
| `toNextAnchor` | 至下一个同级锚点 | 用于多行描述块 |
| `AFTER_ANCHOR(N)` | 锚点后 N 字符内 | 截到自然边界（标点/换行），不要截半句话 |
| `TABLE.locate=firstTableAfterAnchor` | 锚点后**第一个**表格 | 锚点与表格之间插入正文段落仍算该表格；插入另一张表则取第一张 |
| `SECTION` | 章节起止之间 | 边界按标题编号推断，跨页合并 |

**勾选式 vs 下划线式**：规则常说"取下划线上的文字"，但合同可能是勾选式（`☑专营、□细分专营、其他形式___/___`，下划线栏空白）。此时取**勾选项的文字**（`专营`），并在内部记下口径偏差；不要因为"下划线为空"就把整条报成空值。

## 5. 表格 / 多值行级提取（ROWS 模式）

**这是最容易出错的地方，严格按下列程序执行：**

```
① 定位表格   锚点 → firstTableAfterAnchor
② 恢复结构   识别表头行；列数 = 各行列数的众数；合并被换行拆散的单元格
③ 列名对齐   按"精确 > 包含 > 同义"匹配表头
             匹配不到 → 该列取空（不要按"第几列"猜）
④ 逐行取值   每行产出 {列名: 值}；跳过全空行、跳过"合计/小计"行
⑤ 行主键     以产品品种/产品名称为主键，归一化后用于配对（见 03 §3）
⑥ 保结构     输出 [{产品品种, 价格}, ...]；拼接只用于写 auditDesc
```

### 常见坑

| 坑 | 后果 | 正确做法 |
|----|------|---------|
| 用表单值去"填"合同值 | 虚假通过（最严重） | 合同没有就报没有 |
| 表头行被当成数据行 | 多一行脏数据 | 表头行必须识别并排除 |
| 表格底部空白行未跳过 | 多出空行、行数对不上 | 跳过全空行 |
| 跨页表格只取到半张 | 漏行 → 误判 | 检测表头重复出现，拼接同一张表 |
| 页眉公司名被当成字段值 | 取值污染 | 跨页重复行标记为页眉页脚 |
| 多个产品 join 后整体比 | 无法定位差异产品 | 保持行结构，逐行判定 |
| 规则要的列不在表头里 | 该行取不到值 | 如实取空，**不要用相近列顶替** |

> 实测一例：规则要「约定销量（件）」列，而合同表头只有「产品品种 / 规格 / 单位 / 是否含包装物 / 乙方进货价（元）/ 建议销售价（元）/ 基础政策」7 列，无销量列 → 如实取空，最终按该条 `judgeRule` 的高风险输出。

## 6. 内部留痕（不输出，但必须做到）

每条结论都要能回答"依据在合同哪一行"，格式：

```jsonc
{ "file": "PLX240000062534_20260930_1.jpg", "page": "终端合作协议书 P1",
  "locator": "2.1 条下方表格第 4 行「乙方进货价（元）」列",
  "quote": "勇闯天涯superX 1*12 66", "confidence": 0.94 }
```

| 字段 | 要求 |
|------|------|
| `file` / `page` | 具体到哪个图片文件、哪份文书的第几页 |
| `locator` | 能让人 30 秒内翻到那一处；表格类必须给到行列 |
| `quote` | **判定所必需的最短原文片段**，一般 ≤60 字；按**首次读数**记录，不改写不翻译、不回头校对 |
| `confidence` | 0–1。印刷体精确命中 ≈0.95+；拍摄件/手写 0.6–0.9 |

**红线**：`quote` 必须来自**实际读到的内容**，不能拿表单值倒推（那等于根本没读）。
手写体允许有识别偏差 —— 记下 `confidence` 即可，**不为了"抄准"而复读或放大**。
`auditDesc` 里引用的原文片段要克制，不整段复制合同。
