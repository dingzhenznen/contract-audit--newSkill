我按 readme 和 财务_合同质检.json 整理成这版文字 workflow：

  1. 入口接收报账单、附件列表、电子影像和用户问题。
  2. 先做附件合并与去重，把报账单里能抓到的文件对象一起汇总成统一的 file_list。
  3. 通过 文件分类_合同质检 从统一文件中筛出合同类附件。
  4. 从报账单中提取合同质检所需字段：员工/供应商-户名、员工/供应商-银行账号、合同名称、稽核
     行号、业务类别。
  5. 从合同补充协议中提取供应商信息，得到 供应商名称 和 供应商账号。
  6. 先做白名单判断：如果供应商名称命中白名单企业，或名称过短，直接判定为 PASS。
  7. 如果未命中白名单，就按补充协议数量分流：
      - 只有 1 份补充协议：直接用这份协议做质检。
      - 有多份补充协议：先清洗、合并、去空，再统一进入质检。
  8. 核心质检规则只有两条：
      - 报账单 员工/供应商-户名 必须等于合同补充协议里的 供应商名称。
      - 报账单 员工/供应商-银行账号 必须等于合同补充协议里的 供应商账号。
        多份协议时，允许匹配任意一条协议记录。
  9. 如果匹配通过，输出 PASS；如果不通过，输出 HOLD，问题归类为 报销单填写问题 / 供应商信息
     错误，并带上对应附件链接。

  这条子流程本质上就是：先定位合同附件，再抽取供应商名称和账号，最后把报账单填写值和合同约定
  值逐条比对。
